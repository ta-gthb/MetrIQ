About the platform

MetrIQ is a web platform for the technical type evaluation of non-automatic weighing instruments (NAWI). It replaces document-centred report preparation with a structured record: the instrument, its metrological characteristics, the tests performed, the observations taken, the calculation that turned those observations into a result, and the review that accepted it are all held as data, with the rule set that governs them.

Scope

The platform covers the test programme prescribed by OIML R 76-1:2006 and R 76-2:2007 for non-automatic weighing instruments, together with the administrative record of an evaluation: the applicant, the manufacturer, the instrument, the laboratory and the responsible staff.

Governance of the rule set

A rule set reaches a live evaluation only after it has been submitted for technical review, reviewed rule by rule against OIML R 76, approved and activated. A rule set activated provisionally by a development or demonstration deployment is labelled as provisional wherever it is used.

Metrological integrity

Errors, corrections, maximum permissible errors and rounding are evaluated in decimal arithmetic by a deterministic engine. Results are reproducible from the recorded observations, and the calculation path does not depend on any AI component.

Accountability

Every state change is written to an audit trail with its actor, time and reason. An approved report is immutable, carries a content hash and a verification code, and can be checked against the record it was produced from.

Evidence

The instrument nameplate photograph must be attached before an evaluation can be submitted for technical review. Files are stored with a content hash and read through time-limited links.

Access control

Permissions are granted to roles, and laboratory scope is applied in the database as well as in the application, so a query that bypasses the API cannot reach another laboratory's records.

Capabilities

Versioned rule sets

Evaluations are calculated against a rule set that carries a version and a fingerprint. It cannot change under a live evaluation.

Deterministic calculation

PASS or FAIL is produced by the engine from the recorded observations, never entered by hand, and every result cites the rule version and clause behind it.

Complete test catalogue

The prescribed tests are held as a catalogue with clause references. Each entry states whether the engine can execute it; entries needing judgement are surfaced rather than omitted.

Structured evidence

Observations, environmental conditions, equipment and usage are recorded as structured data, with the photographs an evaluation is required to carry.

Laboratory-scoped teams

Every account is registered against a laboratory, and a case is staffed only from that laboratory's register, so personnel are never mixed between laboratories.

Discussion and support

Each evaluation carries a discussion for its team, and every account can raise a private support thread with the Super Admin.

Traceable workflow

Assignment, testing, technical review, correction, verification and approval are distinct recorded states. A correction carries its reason, and no stage is skipped.

Hash-verifiable reports

An approved evaluation produces a PDF or DOCX report under a versioned template, carrying a content hash and a verification code.

Audit trail

Creation, edits, reviews, approvals and downloads are recorded with actor, time and reason, and the trail is readable by the Super Admin.

Role-based access

Super administrator, laboratory administrator, engineer, reviewer and approver roles, each with the permissions its work requires and no more.

Bounded AI assistance

AI may read an instrument nameplate and raise anomalies for attention. It never decides compliance, and its answers cite the rule version and clause they came from.

Interface

Light and dark presentation, a clock synchronised with the platform, and keyboard-accessible controls on every page.
